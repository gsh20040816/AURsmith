# AURsmith v0.1.0-alpha.2 发布说明

这是面向单用户、1～2 台 Arch Linux 客户端的第一版完整预发布候选。它保留 alpha.1 的四角色容器化架构，并补齐真实受限 Fetch 下载、完整 Release 大文件证据、pacoloco 指标、随机高成本复查和 Controller HTTPS/CA 引导。

## 本版完成内容

- Fetch VM 保持 QEMU `restrict=on`，经 Attempt 独占回环中继和 Publisher source proxy 实际下载并验签官方构建依赖；Build VM 继续固定 `-nic none`。
- Profile 支持自定义 Arch HTTPS 镜像，包含完整 pacman 配置、Arch keyring 和所需 virtio/9p 驱动。
- 每个成功 Build 的完整 Profile、Source、License、Fetch/Build/QEMU 日志和签名 JobSpec 作为大文件证据进入 Release、GPG Manifest、ArchiveReceipt 与恢复测试。
- pacoloco 以独立无特权容器运行，缓存命中/未命中进入 Publisher 心跳和 Controller 指标。
- Agent 仍只支持 Codex 与 Claude Code；三低成本 Agent 的 3/2/不超过 1 票规则不变。随机高成本复查默认 0，可由设置页以基点启用。
- Controller 默认使用持久化 Caddy 内部 CA 和 HTTPS；管理员可下载根证书，Doctor 检查有效期，也可通过 Compose override 使用用户证书。

## 已执行门禁

- `bash scripts/test-all.sh`：113 个 Rust 测试、TypeScript 检查、8 个 Vitest 用例、前端生产构建和四套 Compose 安全策略全部通过。
- 非 privileged Builder 容器内真实 KVM Fetch 下载并验签 `tree 2.3.2-1` 成功。
- 无特权只读 Web Caddy 容器实际生成内部 CA 和站点证书，HTTPS 请求及 30 天有效期检查通过；用户证书 Caddyfile 通过真实校验。
- 断网 Signer、Publisher 原子发布、Archiver 递归证据恢复和 pacman 安装/升级/回滚/显式降级沿用已记录的实际验证。
- 当前提交使用 annotated Git tag `v0.1.0-alpha.2` 固定；仓库没有 remote，因此不声称已经推送或创建托管平台 Release。

## 部署时仍需人工验收

1. 准备并离线备份 Controller、GPG、SSH、Agent API key、内部 CA 和管理员恢复材料。
2. 配置局域网 DNS、Worker 固定 SSH host key、Publisher 仓库域名和客户端仓库顺序。
3. 使用自己的 Codex/Claude provider 凭据对非关键包执行首次真实审计；当前开发机没有这些凭据，本发布没有伪造成功记录。
4. 在实际独立存储设备上完成一次 Controller 与 Release 恢复演练，并验证 Webhook/ntfy。
5. Profile 优化需要至少 20 次真实构建积累数据；初始阶段只展示建议。

## 回滚

服务端可切换到任一已有签名 Release。客户端不会自动降级，应使用 Web 生成的归档 `pacman -U` 命令。控制面恢复必须停机，并保留恢复前数据库副本。
